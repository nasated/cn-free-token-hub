# 活动雷达：采集与核验规则

## 产品范围

收录国内外、主流与新产品的大模型 Token 赠送、限时免费、价格折扣和低价调用。每条活动必须区分 API 可调用、产品内专用或暂不确定。固定新用户额度保留在旧列表；人工整理活动优先展示，其次按消息时间展示自动线索。

## 两条数据通道

1. `scripts/discover.ts` 每半小时计划检索 Google News RSS、V2EX Atom 与 Bluesky 公共搜索。提取标题、发布时间、本站发现时间、原帖或聚合链接和来源名称，写入 `data/leads.json`。所有自动记录均为 `unverified`，不会自动填写活动金额、价格、参与条件或期限。
   每轮在 Action 摘要中记录新闻、社区、社交来源的成功和失败数；任一来源失败产生警告，新闻搜索全部失败则任务报错，避免其他来源可用时掩盖新闻源故障。
2. 人工核对可读来源后，把活动写入 `data/campaigns.json`。仅有媒体报道时标为 `reported`，报道中的日期范围可用文字记录，但页面明确“待官方核实”。直接核对官方规则并有证据摘要时才标为 `verified`。`npm run build` 会先运行 `scripts/validate-activities.ts`。

将自动线索整理成活动时，可在该活动的 `sourceLeadIds` 中填写原线索 ID，页面会折叠重复线索，发现任务下次运行时会从 `leads.json` 清除它。

这些公开源不是全网实时抓取。搜索引擎索引延迟、GitHub Actions 排队或丢失任务、登录墙、接口限流和图片内文字都会导致漏报。小红书、公众号、应用内弹窗等来源需要原始链接、官方可读入口或用户投稿；不得把截图推断当作官方规则。自动线索会过滤明显的邀请码和返佣帖；其他社区推广仍需核对价格及适用范围。

## 时间语义

| 字段 | 含义 |
| --- | --- |
| `publishedAt` | 原消息发布时间，不代表活动开始。 |
| `discoveredAt` | 本站首次发现该线索的时间。 |
| `verifiedAt` | 人工核对规则的时间。 |
| `claimWindowApplicable` | 是否有独立的领取／发放窗口；纯免费使用和自动降价可为 `false`。 |
| `claimStartAt` / `claimEndAt` | 可以领取的窗口。 |
| `claimStartDate` / `claimEndDate` | 只公布日历日期时的领取范围，不能据此推断具体时刻。 |
| `claimWindowText` | 只有日期范围、没有具体时刻时的来源表述。 |
| `useStartAt` / `useEndAt` | 已领取额度可使用的窗口。 |
| `useStartDate` / `useEndDate` | 只公布日历日期时的使用范围。 |
| `useWindowText` | 使用或优惠期限只有文字规则时的来源表述。 |
| `validityRule` | 例如“领取后 7 天有效”或“每天 24:00 清零”，不能误写成统一绝对日期。 |

具体时刻使用 ISO 8601 且带时区偏移，例如 `2026-09-24T23:00:00+08:00`。若仅有“9 月 28 日至 10 月 7 日”，写入 `claimStartDate`、`claimEndDate` 和带依据的 `claimWindowText`，具体时刻保持 `null`；页面只会在最后一个北京时间日历日结束后将其标为结束。若来源没有给出时间则保持 `null`，页面显示“未公布／待核实”。“首期两周”“72 小时内上线”不能在缺少实际启动时间时推算截止日期。

## 核验清单

- 原始活动链接及官方规则是否可访问；新闻聚合链接只能作为线索。
- 额度是否可通过通用 API Key 使用，还是仅限某个产品、Coding Plan 或会员。
- 赠送额度、折扣前后价格、货币、每百万输入/输出 Token 计费单位、适用模型与上限。
- 是否限新人、实名、付费会员、地区、先到先得或指定日期登录。
- 领取与使用各自的开始/截止时间；若滚动有效，记录规则和时区。
- 活动结束、延期或规则变化时保留原记录并更新来源和状态，不凭关键词命中自动宣称有效。

## 本地运行

`npm run discover` 使用 Node 原生网络请求。在使用 Windows 系统代理的电脑上，若 Node 直连超时，可仅为当前 PowerShell 进程设置 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NODE_USE_ENV_PROXY=1` 后运行；不要把个人代理地址或凭据写入仓库。GitHub Actions 的 Node 22 runner 使用自身网络环境。

## 验收目标

对已接入且可公开读取的来源，计划每半小时检索，目标是在消息发布后 30–60 分钟内显示为“待核实线索”；这不是全网保证，也不代表 60 分钟内完成官方核验。活动卡显示来源、使用场景、领取与使用时间或明确“未公布”。上线后要监测计划任务成功率、消息到发现的延迟，以及误报和漏报。
