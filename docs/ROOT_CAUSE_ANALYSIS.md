# 活动内容缺失的根因与修复边界

## 直接观察到的根因

1. 旧版 `scripts/crawl.ts` 只读取 `data/platforms.json` 中固定的 13 个 `verifyUrl`，每天运行一次。它不会发现新产品或新活动，所以首页自然长期以注册赠额为主。
2. 旧脚本只检查网页是否可达及 Token 等关键词，不提取金额、价格、领取开始/截止、到账后使用期限，也不区分 API 与产品内额度。旧版页面没有活动时间模型。
3. 旧脚本曾将“关键词稳定”升级为 `verified` 并刷新 `lastVerified`。这不等于人工读过官方规则，旧资料的核验标记不能继续作为“活动正在有效”的证据。
4. 小红书图片、应用内弹窗和登录后才可读的活动不一定进入公开新闻索引。单靠新闻搜索不能保证抓到用户截图中的三类活动。[GitHub 官方文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)也说明计划任务可能延迟或丢失，因此 30–60 分钟只能是已接入公开来源的目标，不能宣称全网保证。

## 本次修复

- 将固定额度与活动分开。活动首页包含自动线索与人工整理卡片，国内外、新产品、产品内赠额、免费调用、折扣和低价调用都在范围内。
- 每 30 分钟计划搜索 Google News RSS、V2EX Atom 和 Bluesky 公共帖。自动线索一律为 `unverified`，金额、有效期和适用场景不从标题臆造。
- 人工核对媒体报道后可标 `reported`；只有直接核对官方价格或活动规则后才能标 `verified`。页面分别显示消息发布时间、本站发现时间、领取/发放窗口、使用/优惠窗口和核验时间。
- 支持精确到时刻的 ISO 时间，也支持“9 月 28 日至 10 月 7 日”这种只有日历日期的范围。仅有日期时不推断 00:00 或 23:59；最后一个北京时间日历日过后才显示领取期结束。
- 自动线索保留 14 天。人工整理活动可通过 `sourceLeadIds` 折叠重复线索。旧版固定额度不再以每日关键词检查冒充人工核验。

## 截图案例的证据边界

目前已整理一个[OpenRouter 官方免费 API 价格页](https://openrouter.ai/stealth/space-bunny-alpha)案例和一个[MiniMax 9 月 28 日至 10 月 7 日签到活动报道](https://m.ithome.com/html/1007530.htm)案例。前者已直接核对官方价格，但结束日期未公布；后者仅核对报道，准确时刻与到账后期限未公布。截图中的三项尚未冒充为已核验活动。

## 上线验收

1. 先在主分支运行一次 `discover` 工作流，确认源请求、提交及 Pages 发布均成功；本地构建不能代替 CI 验证。
2. 连续记录消息发布时间到线索发现、线索发现到网站发布的耗时。对已接入且公开可读的来源，以 30–60 分钟为目标，并单独记录超时及漏报。
3. 每天抽查社区推广与新闻线索的误报，核对人工整理卡片的原始链接、适用模型、原价/活动价、会员限制、领取和使用两个期限。
4. 用户截图所涉社交平台若持续漏报，需要取得可公开读取的官方/原帖链接、稳定来源或合规接口；公开 RSS 无法替代这些来源。
